### #15059: Multiple system prompts break Qwen3.5-* models

- **種別**: Bug
- **報告者**: DaGhostman
- **報告日**: 2026-02-25
- **ラベル**: `bug`, `core`
- **内容**: OpenCode がモデルに複数の system メッセージを送信するため、Qwen3.5 モデルが動作しない。Qwen3.5 の chat_template (Jinja) は system メッセージが 1 つだけであることを前提としており、複数あるとエラーになる。プラグイン（opencode-dynamic-context-pruning）が追加の system プロンプトを挿入することで問題が顕在化した。
- **再現手順**:
  1. `@tarquinen/opencode-dcp` (v2.1.7 以下) をインストール
  2. Qwen3.5 モデルでセッションを開始
  3. メッセージを送信 → エラー発生
- **提案された修正**: 複数の system プロンプトを 1 つに結合してからモデルに送信する
- **ステータス**: Open、修正 PR #15018 が提出済み

### 最も深刻な問題: 複数システムプロンプト問題

**Issue #15059, #5034, PR #15018** が示す通り、OpenCode が複数の system メッセージを送信する設計は、Qwen3.5 を含む多数のモデルで致命的なエラーを引き起こす。この問題は 2025年12月から報告されており（#5034）、3ヶ月以上未修正のまま、影響を受けるモデルが拡大し続けている。

**PR #15018** が提出されており、非 Anthropic プロバイダーに対して system プロンプトを結合する修正が実装・検証済み。コミュニティからもマージ促進のコメントが出ている（#5034 の cyangle, paulgear）が、**レビューは依然 0件**で停滞している。

### ツール呼び出しの問題

**Issue #6918** に代表されるツール呼び出し失敗は、モデル側（不正な JSON 出力）と llama.cpp 側のバグの複合問題。**PR #14744** がツールスキーマの引数順序変更による修正を試みているが、Skyedra (2/28) のテスト結果では部分的改善に留まり、根本解決には至っていない。

### プロバイダー対応

- NVIDIA NIM のモデルリストが静的管理のため、新モデル（qwen3.5-397b-a17b など）の追加が遅れている
- #10760 で Qwen3.5-397B-A17B での unmarshal エラーが確認され、NVIDIA プロバイダー経由での Qwen3.5 利用に追加の障壁

### コミュニティの動き

- Qwen3.5-Plus 用プラグイン（#14111）やネイティブプロバイダー追加 PR（#15102）など、コミュニティ主導での Qwen3.5 サポート拡充が進んでいる
- ただし #15102 にはクローズ提案が出ており（vadim-isakov: BUILTIN_PROVIDERS ハードコーディングはアンチパターン）、方向性に議論あり
- 根本的なバグ修正（#15018）もコミュニティメンバーから提出されているが、メンテナーによるレビューが滞っている
