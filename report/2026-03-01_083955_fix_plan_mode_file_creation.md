# Plan モードでのファイル作成問題の修正レポート

- 日時: 2026-03-01 08:39
- 作成者: Claude

## 前提条件・目的

- 目的: opencode の plan モードで LLM がレポートファイルを直接作成してしまう問題を修正する
- 前提: plan モードは読み取り専用であり、計画ファイル以外のファイル作成は禁止されている
- 問題: CLAUDE.md のレポート作成ルールやユーザーの明示的な依頼により、plan モードの制約がシステムプロンプトより低い優先度のリマインダーにしか存在しないため無視される

## 原因分析

3つの要因が組み合わさっている:

1. **システムプロンプトに plan モード制約がない**: plan モードのリマインダーはユーザーメッセージ内の `<system-reminder>` にのみ存在し、システムプロンプト（最高優先度）には含まれていなかった
2. **experimental モードで継続リマインダーがない**: experimental plan モードでは初回のみリマインダーが挿入され、2ターン目以降は挿入されない
3. **ファイル作成リクエストへの対応が不明確**: プロンプトがコード実装の計画に焦点を当てており、レポート等のファイル作成依頼への対応が明示されていなかった

## 作業内容

対象ファイル: `packages/opencode/src/session/prompt.ts`

### 修正1: システムプロンプトに plan モード制約を追加（652行目付近）

agent が plan の場合、システムプロンプトに plan モードの制約を追加。これにより LLM の最高優先レベルで制約が認識される。

### 修正2: 初回 plan モードプロンプトにファイル作成禁止を明示（1391行目付近）

既存の plan モード初回リマインダーに、レポート・ドキュメント等のファイル作成を直接行わず計画として記述すべきことを明示する文言を追加。

### 修正3: experimental plan モードに継続リマインダーを追加（1466行目付近）

`input.agent.name === "plan" && assistantMessage?.info.agent === "plan"` の条件（plan モード継続中）で、簡潔なリマインダーを毎ターン挿入するように追加。

## 再現方法

1. opencode をビルドして起動
2. plan モードに入る（@plan）
3. 以下のプロンプトを送信:
   「Railsのバージョンアップに備えて、不足しているテストと、修正すべき箇所の提案を、レポートにまとめてください。レポートはreportディレクトリに作成してください」
4. LLM がレポートファイルを直接作成せず、計画ファイルに調査・レポート作成の計画を記載することを確認

## 結果・所見

- 3箇所の修正により、plan モードでのファイル作成問題に多層的に対処
- 最も重要なのは修正1（システムプロンプトへの追加）で、LLM の優先順位の最上位で制約を認識させる
- 修正3は experimental モード固有の問題（継続リマインダーの欠如）を解消し、長い会話でも制約が薄れないようにする
- bun が環境にインストールされていないためビルド確認は未実施。変更は文字列の追加と条件分岐のみで、型安全性に影響なし
