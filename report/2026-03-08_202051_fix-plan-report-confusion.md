# plan モードでのレポート作成とプラン内容の混同問題の修正

- 日時: 2026-03-08 20:20
- 作成者: Claude

## 前提条件・目的

- 目的: plan モードで「レポートを作成してください」と依頼すると、LLM がプランファイルに直接レポート内容を書いてしまう問題を修正する
- 証拠: `ytdlor/.opencode/plans/` 内の複数のプランファイル（300〜400行超）にレポート本文が直接記述されていた
- 根本原因: プロンプト内で「プラン＝build モードで実行する手順書」という概念が明示されておらず、「成果物の内容 ≠ プランの内容」という区別が不明確だった

## 作業内容

3箇所のプロンプトを修正し、以下を明確化:

### 1. システムプロンプト (`prompt.ts:655-656`)
- plan ファイルが「手続き的ドキュメント（PROCEDURAL DOCUMENT）」であることを明記
- レポート等の成果物を依頼された場合は、ファイルパス・構造・セクション・調査手順を記述し、実際のレポート内容は書かないよう指示

### 2. plan モード開始時リマインダー (`prompt.ts:1422-1435`)
- DO / DO NOT の箇条書きで明確なガイダンスを追加
- 正しいプランと誤ったプランの具体例（テストカバレッジレポートの例）を追加

### 3. plan.txt の Responsibility セクション
- plan の定義（「build エージェントへの指示セット」）を追加
- ドキュメント・レポートタスクでは成果物の内容ではなく手順を書くよう注意書きを追加

## 再現方法

1. `cd packages/opencode && bun run build --single` でビルド
2. opencode を起動し、テストプロジェクトで plan モードでレポート作成を依頼
3. LLM がプランファイルに手順書（ファイルパス、セクション構成、調査手順）を書き、レポート本文を直接書かないことを確認
