# CLAUDE.md Bash コマンドルール強化レポート

- 日時: 2026-03-09 07:58
- 作成者: Claude

## 前提条件・目的

- 目的: Bash コマンド実行時に頻発する承認プロンプトを削減するため、CLAUDE.md のルールを強化する
- 背景: 既存ルールがカバー済みのパターンで繰り返し違反が発生しているほか、ルールが存在しない新規パターンも発見された

## 作業内容

### 1. 原則の追記

禁止事項セクションの冒頭に判断原則を追加:
- 「判断に迷ったら、承認プロンプトが出そうな構文は避ける」
- シェル演算子（`|`, `||`, `;`, `>`, `<`, `$()`, バッククォート, `\`, `(`, `)` など）を含むコマンドは承認対象になりやすいことを明記

### 2. 既存ルールの強化

| ルール | 変更内容 |
|--------|---------|
| Rule 4 (リダイレクト) | `2>&1` を明示的に NG 例として追加 |
| Rule 5 (パイプ) | `\| head -20`, `\| grep -v`, `\| tail -5` を NG 例として追加。git 自体のオプションで件数制限する OK 例を追加 |

### 3. 新規ルールの追加

| ルール | 内容 |
|--------|------|
| Rule 10 | `find` コマンド禁止 — Glob / Grep ツールで代替。`-exec \;` や `\( \)` が承認対象になる理由も記載 |
| Rule 11 | `;` (セミコロン) によるコマンド分離禁止 — 別々の Bash 呼び出しに分割 |
| Rule 12 | `export && command` 連結禁止 — `env VAR=value command` 形式で代替 |
| Rule 13 | `echo` をコマンド出力に使わない — 区切り文字や確認メッセージは Bash ツール外で記載 |

## 結果・所見

- 全13ルール（既存9 + 新規4）と判断原則により、承認プロンプトの発生パターンを網羅的にカバー
- 各ルールに NG/OK 例を付記し、具体的な代替方法を明示した
- 新規セッションでの効果検証が必要（ルールが正しく遵守されるかの確認）
