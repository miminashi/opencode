- 日時: 2026-03-17 06:03
- 作成者: Claude

## 前提条件・目的

- 目的: Claude Code が生成するコマンドで承認プロンプトが発生する2つのケースに対処する
- 背景: `settings.local.json` の allow ルール（`Bash(echo:*)` / `Bash(find:*)`）が存在するが、Claude Code のセキュリティチェックがこれらをオーバーライドするため、CLAUDE.md で AI がこれらのコマンドを生成しないよう指示する必要がある

### 報告されたケース

1. `echo $?` → `$?` の特殊変数展開チェックにより承認を求められる
2. `find ... -exec grep ... \;` → "backslash before shell operator" チェックにより承認を求められる

## 作業内容

`/home/ubuntu/projects/opencode/CLAUDE.md` に以下の3つの変更を適用:

### 変更 1: echo コマンド禁止ルール（14-17行目）

「専用ツールの優先使用」セクション末尾に追加:
- `echo $?` は Bash ツールの仕組み上常に 0 で意味がないことを説明
- 変数展開（`$VAR`）がセキュリティチェックに引っかかることを注記
- 代替手段を提示

### 変更 2: バックスラッシュ+シェル演算子禁止ルール（42-45行目）

「複合コマンドの禁止」セクション末尾に追加:
- `\;` `\|` `\&` `\<` `\>` を含むコマンドの禁止
- `find -exec \;` → Glob + Grep ツールで代替
- `grep "pat1\|pat2"` → Grep ツールで代替

### 変更 3: 「複雑なコマンドのスクリプト化」新セクション（47-54行目）

「複合コマンドの禁止」セクションの直後に新セクション追加:
- `./tmp/` ディレクトリにスクリプトを配置する方法
- Write ツールでスクリプト作成 → `bash ./tmp/search.sh` で実行するワークフロー

## 結果・所見

- 3つの変更がすべて正しく適用された
- 既存のセクション構造を維持しつつ、新ルールが自然に統合された
- 検証は次回の Claude Code セッションで、同様のタスクを依頼して承認プロンプトが出ないことを確認する
