## v2 → v4 の変更と効果

### 1. LLM モデル変更（独立変数）
- **変更**: Qwen3.5-35B-A3B → Qwen3.5-122B-A10B（アクティブパラメータ 3B → 10B）
- **効果**:
  - **指示遵守の向上**: v2 で頻発した `--no-cache` ループが激減（CLAUDE.md 禁止指示を遵守）
  - **自己修復能力**: Ruby バージョン互換性問題、テスト構文エラー、Gemfile 制約等を自力で解決
  - **RSpec 構文混入の減少**: CLAUDE.md 強化後は `double()` 使用なし
  - **速度低下**: 平均所要時間が v2 の 67分から v4 の 178分に大幅増加（約2.7倍）

### 2. Bash タイムアウト延長（iter 54 → 55）
- **変更**: 600000ms (10分) → 1200000ms (20分)
- **効果**: テスト実行率 0% → 100% に劇的改善。Docker build の完了を待てるようになった
- **v2 との対応**: v2 でも iter 15 で 120000ms → 600000ms に延長（同種の改善）

### 3. CLAUDE.md 改善（2回のみ）
- iter 53→54: Minitest 強化（`double` 禁止）、`--no-cache` 禁止、fixtures アンコメント禁止
- iter 54→55: bash タイムアウト表記を 20分に更新
- **v2 との比較**: v2 では 8回の改善が必要だったが、v4 では 2回で安定化。122B モデルの指示遵守力が高いため

## 発見と知見

### 1. モデルサイズの効果

122B モデル（10B active）は 35B モデル（3B active）に比べて:
- **指示遵守**: CLAUDE.md の禁止事項を守る確率が大幅に向上（`--no-cache` 使用率の低下、RSpec 構文混入の減少）
- **自己修復**: エラー発生時に自力で問題を分析し修正できる（Ruby バージョン変更、minitest ピン留め等）
- **判断力**: ただし「ダウングレード禁止」制約とランタイム互換性エラーが矛盾する場合、LLM はランタイムエラーを優先してダウングレードを選択する（iter 61,62）
- **速度**: 推論速度は約2.7倍遅い（plan phase が特に顕著）

### 2. Ruby 3.3.0 vs Rails 8.1 の互換性問題

- v2-base の CLAUDE.md は Ruby 3.3.0 を指定しているが、Rails 8.1.3 の ActionView は anonymous rest parameter を使用しており Ruby 3.4+ が必要
- 122B モデルはこの互換性問題に遭遇すると、2つの戦略を取る:
  - **成功パターン** (iter 55-58): Ruby を 3.3.x の別バージョン（3.3.1, 3.3.3, 3.3.6, 3.3.7）や 3.4 に自力で変更
  - **失敗パターン** (iter 61,62): Rails を 8.0.5 にダウングレード
- この判断はセッションの状態（Context 使用率、時間経過、エラーの種類）に依存する不確定要素

### 3. bash タイムアウトの重要性

- v2 と v4 の両方で、Docker build タイムアウトが最大のボトルネック
- Ruby ベースイメージ変更時はフルリビルドが必要で、10分では不足
- 20分に延長するだけでテスト実行率が 0% → 100% に改善

## コードレビュー総括

- 全10回を通じて、テストの方向性は一貫して合理的（model のステータスヘルパー、scope、callback をカバー）

### プロダクションコード変更
- app/ 配下の変更: 0回（10回中0回） — v2/v3 と比較して最も良好
- config/boot.rb 変更: 1回（iter 59、bootsnap コメントアウト）

## 結論

1. **テスト実行率は v2 の 20% から v4 の 80% に大幅改善** — 122B モデルの指示遵守と bash タイムアウト延長の複合効果
2. **全条件達成率は v2 の 10% から v4 の 40% に改善** — ただし v3 後半（64%）には及ばない
3. **所要時間は v2 の 67分から v4 の 178分に増加** — 122B モデルの推論速度がボトルネック
4. **CLAUDE.md 改善は 2回で安定化** — v2 の 8回と比較して大幅減少。モデルの指示遵守力が高いため改善の必要性が低い
5. **Ruby 3.3.0 と Rails 8.1 の互換性問題が未解決** — v2-base の CLAUDE.md には v3 で発見された Ruby 3.4.1 の知見がないため、LLM の判断に依存する不確定要素が残る
6. **122B モデルの最大の長所は自己修復能力** — エラー発生時に自力で問題を分析し修正できる（35B では同じ操作をループする傾向があった）
