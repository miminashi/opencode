## 実験経緯

### 環境問題の発見と対処

実験開始時に 2 つの環境問題が発見された:

1. **LLM サーバーの ctx-size (16K)**: 初回試行でセッションが context length ループに陥り停止。llama-server を ctx-size 32768 (32K) に変更して再起動
2. **opencode.json の context 不一致 (131K vs 32K)**: 2回目試行で TodoWrite JSON パースエラー発生。opencode.json の context を 32768 に修正

## 分析

### 1. プロンプト制約の効果（主要な研究課題）

iter 63（唯一の完走ケース）の制約遵守状況:

| 制約 | プロンプト(v4) | CLAUDE.md | iter 63 遵守 |
|------|---------------|-----------|-------------|
| `&&`/`;` 禁止 | ✓ | ✓ | ✓ |
| app/ 不変 | ✓ | ✓ | ✓ |
| コメントアウト維持 | ✓ | ✓ | ✓ |
| Gemfile.lock 保護 | ✓ | ✓ | ✓ |
| 外部サービスモック | ✓ | ✓ | △ |
| Docker テストコマンド | ✓ | ✓ | ✓ |
| Ruby 3.3.0 指定 | ✗ | ✓ | **✗ (3.3.7)** |
| ユーザーに質問しない | ✗ | ✓ | **✗ (2回質問)** |
| テスト追加 | プロンプト手順 | CLAUDE.md | **✗ (スキップ)** |

**所見**: プロンプトにも CLAUDE.md にも記載された制約（6項目中5項目）は遵守された。しかし、CLAUDE.md のみに記載された制約（Ruby 3.3.0、質問禁止）は遵守されなかった。

### 2. context サイズの影響（想定外の交絡因子）

v5 実験で最大の障害となったのは、プロンプト制約の有無ではなく **context サイズの問題** だった:

- **v4**: opencode.json context=131072、サーバー ctx-size=16K → opencode は会話履歴を大量に保持し、API 呼び出しごとに rolling truncation で 16K に収める
- **v5**: opencode.json context=32768、サーバー ctx-size=32K → opencode は会話履歴を 32K で頻繁に compaction → LLM が文脈を喪失

plan_exit ループの原因は、compaction 後に LLM が「plan_exit は既に承認された」という情報を忘失し、再度 plan_exit を呼び出すことだった。v4 ではこの問題が発生しなかったのは、opencode が 131K の会話履歴を保持していたため。

### 3. CLAUDE.md の読み込みと制約の保持

- **読み込み**: 3 回とも LLM は CLAUDE.md と skills/ を読み込んだ（画面で確認）
- **初期理解**: plan phase では制約を正しく理解していた（Compaction サマリに「Critical Constraints: DO NOT Modify app/」等が記載）
- **compaction 後の喪失**: 複数回の compaction を経ると、詳細な制約（Ruby 3.3.0 指定、質問禁止等）が失われた

## 結論

### プロンプト制約の必要性

**判定: 結論を出すにはデータが不十分。ただし暫定的には「重要な制約はプロンプトに残す」が推奨。**

- プロンプトの制約セクションに直接対応する 6 項目のうち 5 項目は、CLAUDE.md のみでも遵守された
- しかし、CLAUDE.md のみに依存した制約（Ruby バージョン、質問禁止）は遵守されなかった
- compaction による文脈喪失が主因であり、context サイズの問題を解決すれば結果が改善する可能性がある

### 実験の限界

1. **交絡因子**: v4 と v5 で opencode.json の context 設定が異なるため、プロンプト制約の効果のみを分離できていない
2. **サンプルサイズ**: 完走 1 回、plan_exit ループ失敗 2 回では統計的な結論は出せない
3. **ctx-size 32K の制約**: v4 実験時と異なる context 管理になったことで、plan_exit ループという新しい失敗モードが出現した

### 推奨事項

1. **opencode.json の context 設定を v4 相当（131072）に戻して再実験する** — context 管理の問題を排除した上でプロンプト制約の効果を検証
2. **重要な制約はプロンプトに残すことを暫定採用** — 特に compaction で失われやすい詳細な制約（バージョン指定等）
3. **CLAUDE.md の制約はプロンプト制約の補完として有効** — 基本的な制約（app/ 不変、`&&` 禁止等）は CLAUDE.md のみでも機能した
