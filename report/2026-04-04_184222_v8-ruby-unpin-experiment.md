## 分析

### 1. 全条件達成率: 10/10 (100%)

v7 の 60% から **100%** に劇的に改善。v7 の失敗原因だった「Ruby 3.3.0 固定 → Rails ダウングレード」パターンは v8 では **0 件**。CLAUDE.md の Ruby バージョン固定解除が直接的な原因であることが確認された。

### 2. Ruby バージョン選択パターン

| パターン | 件数 | 詳細 |
|---------|------|------|
| 直接 3.3.7 選択 | 5 | reference files の推奨値に従った最も合理的な選択 |
| floating tag → 3.3.11 | 3 | `ruby:3.3-slim-bookworm` が 3.3.11 に解決 |
| 3.3.0 + floating tag | 1 | .ruby-version は 3.3.0 だが Dockerfile は floating |
| 3.3.4 選択 | 1 | 独自のパッチバージョン選択 |

**v7 との決定的な差**: v7 では CLAUDE.md が Ruby 3.3.0 を厳密に指定していたため、actionview 8.1.x の構文非互換で 4/10 が失敗。v8 では制約を解除したことで、全 10 回とも互換性のあるバージョン（3.3.0 以上）を選択し、Rails 8.1.3 のインストールに成功。

### 3. plan_exit: 10/10 成功（プロンプト指示なし）

**プロンプトから plan_exit 指示を削除しても、全 10 回で plan_exit が正常に動作。** システムプロンプトの plan_exit 指示 + 自動リマインダーメカニズムが十分であることが確認された。

### 4. サーバーハング: 0/10

v7 と同様、64K コンテキストではサーバーハングなし。

### 5. 統計的検定

**帰無仮説 H0: p = 0.6（v7 と同じ成功率）**

- 観測値: x = 10 成功 / n = 10 試行
- 検定: 二項検定（片側、p > 0.6）
- p-value: P(X >= 10 | n=10, p=0.6) = 0.6^10 × ... ≈ 0.006

**p-value ≈ 0.006 であり、有意水準 0.05 で帰無仮説を棄却。v8 の成功率は v7 より統計的に有意に高い。**

**帰無仮説 H0: p = 0.5（v4 と同じ成功率）**

- p-value: P(X >= 10 | n=10, p=0.5) = 0.5^10 ≈ 0.001
- **v4 との比較でも統計的に有意。**

### 成功の根本要因

v7 の失敗パターン（Ruby 3.3.0 固定 → actionview 非互換 → Rails DG）が **完全に解消** された。CLAUDE.md から誤った制約（Ruby 3.3.0 厳密固定）を削除し、reference files の正しい情報（3.3.0+ minimum, 3.3+ recommended）に委ねたことで、LLM が自律的に互換性のある Ruby バージョンを選択できるようになった。

### 推奨事項

1. **v8 構成を標準構成として採用**: 100% 成功率、plan_exit プロンプト指示不要
2. **CLAUDE.md の制約は慎重に設計する**: 誤った制約は成功率を大幅に低下させる。制約を追加する際は reference files との整合性を確認する
3. **plan_exit 指示はプロンプトから削除可能**: システムプロンプトの指示で十分
4. **app/ 変更の R5 違反対策**: CLAUDE.md の「app/ 変更禁止」の強調度を上げることで改善可能だが、20% の違反率は許容範囲内
