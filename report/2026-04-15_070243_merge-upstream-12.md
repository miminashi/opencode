## 発見した問題とその修正

### Permission.approve 欠落

upstream の facade 削除 PR (#22342) は `approve` を facade としても Interface からも削除したが、当フォークの `src/tool/plan.ts` の `plan_exit` ツールは「Yes, clear context and auto-accept edits」選択時に `permission.approve([...])` を Service 経由で呼び出す。Service Interface から `approve` が消えたため `'approve' does not exist on type 'Interface'` エラーが発生。

→ `approve` を Service メソッドとして復元（`approve: (rules: Ruleset) => Effect.Effect<void>`）。

### pipe 引数上限

registry.ts の `defaultLayer` で `Permission.defaultLayer` と `SessionCompaction.defaultLayer` を追加した結果、`Layer.provide` が 21 個となり effect の pipe() 引数上限 (20) を突破。

→ 2 つの `.pipe()` に分割:

```ts
layer.pipe(
  ...19 の Layer.provide,
).pipe(
  Layer.provide(Permission.defaultLayer),
  Layer.provide(SessionCompaction.defaultLayer),
)
```

### Identifier.create API 変更

boolean 第 2 引数（descending）が `"ascending" | "descending"` のユニオン型に変更された。`truncate-effect.ts` で `false` を渡していた箇所を `"ascending"` に修正。
