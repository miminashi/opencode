## コンフリクト解消

マージ時に 10 ファイルでコンフリクトが発生した。解消方針は「upstream の構造 (namespace 解体・Schema 化後) を採用しつつ、ローカルのカスタム機能を残す」方針で統一。

### 1. `packages/opencode/src/cli/cmd/tui/util/clipboard.ts`

- upstream が `Clipboard` namespace を平坦化し、top-level `Content` 型 + `copy()` 関数に変更
- ローカルの OSC52 DCS passthrough (`OscCopier` / `writeOsc52ViaRenderer`) を保持
- `OscCopier` から `lib` / `rendererPtr` の明示フィールドを削除 (CliRenderer の private フィールドと衝突するため). 実体は `(renderer as any).lib` で参照

### 2. `packages/opencode/src/cli/cmd/tui/util/selection.ts`

- `import { Clipboard, type OscCopier }` → `import * as Clipboard` + `type OscCopier` に変更
- `Clipboard.copy(text, renderer)` のシグネチャは変更なし (第二引数で renderer を渡す)

### 3. `packages/opencode/src/permission/index.ts`

- upstream が `PendingEntry` インターフェースと reject 時の session 内カスケード reject を追加
- `Interface` に `readonly approve: (rules: Ruleset) => Effect.Effect<void>` を追加 (ローカル機能: plan_exit の auto-accept edits で使用)
- `layer` 内の `Service.of({ ask, reply, list, approve })` に `approve` の実装を追加

### 4. `packages/opencode/src/session/compaction.ts`

- upstream が compaction を大幅リファクタ: `SUMMARY_TEMPLATE` / `turns` / `splitTurn` / `buildPrompt` / `preserveRecentBudget` 導入、`makeRuntime` ベース
- ローカル機能を以下のように統合:
  - `discoverStateFiles(directory)` → `Effect.promise` 版に書き直して `buildPrompt` の context に注入
  - `extractUsedSkills` / `skillReloadHint` → autocontinue メッセージの末尾に付加
- `InstanceState.context` は `SessionCompaction.Service` 配下の新しい場所から取得

### 5. `packages/opencode/src/session/message-v2.ts`

- upstream が `CompactionPart` を Effect Schema で再定義 (`auto`, `overflow`, `tail_start_id`)
- ローカルの `continueText` / `clear` フィールドを `Schema.optional` として追加
- user message 側の compaction text を `part.clear` 条件に応じて切替 (Context was cleared / What did we do so far)
- 古い zod ベースの `CompactionPart` 重複定義 (HEAD 側ブロック) を削除

### 6. `packages/opencode/src/session/prompt.ts`

- 最大の衝突。upstream が `title()` に `real()` ベースの判定と `subtasks` 対応、および `insertReminders()` の独立関数化を行った
- ローカルの plan mode 強化版 `insertReminders()` 本体を保持 (非実験・実験両モードの詳細なシステムリマインダー、post-compaction plan→build 検出、continueText 再利用)
- `runLoop` 内で upstream 側の `handleSubtask` 呼び出し構造を採用しつつ、以下のローカル機能を再注入:
  - `planExitReminderCount` / `MAX_PLAN_EXIT_REMINDERS` / `truncationRetryCount` / `MAX_TRUNCATION_RETRIES` カウンタを runLoop 頭で宣言
  - `agent.name === "plan"` 時に追加のシステムメッセージを `system[]` に push
  - `finish === "length"` で invalid tool part が出たときの truncation retry (token limit 超過検出)
  - `result === "stop"` で plan_exit を呼ばず終わった場合のリマインダー送信
- `MessageV2.parts(handle.message.id)` を使って assistant parts を取得 (同期)

### 7. `packages/opencode/src/session/retry.ts`

- upstream が 5xx transient failure の自動リトライを追加 (`statusCode >= 500`)
- ローカル機能 (llama.cpp の "failed to parse input" を `/failed to parse input/i` で判定し `"Tool call parse error, retrying"` を返す) を `retryable()` 冒頭に保持

### 8. `packages/opencode/src/tool/registry.ts`

- upstream の layer / defaultLayer 構造を採用
- `Permission.Service` と `SessionCompaction.Service` を layer の required services に追加 (plan.ts が `permission.approve` と `compaction.create` を使うため)
- `defaultLayer` の `.pipe(Layer.provide(...))` 連鎖が 20 を超えるため 2 チェーンに分割し、末尾で `Permission.defaultLayer` と `SessionCompaction.defaultLayer` を注入
- `tool.plan` を常時 builtin に含める (upstream の `Flag.OPENCODE_EXPERIMENTAL_PLAN_MODE && Flag.OPENCODE_CLIENT === "cli"` 条件を外す)
- HEAD 側にあった `Env.Service` / `FileTime.Service` の依存は古い merge 痕跡のため削除

### 9. `packages/opencode/src/tool/truncate.ts`

- upstream が `write` / `limits` メソッドと `tool_output` config 対応を追加
- ローカルの rolling truncation (head + tail + marker) を `output` 関数内に統合
- `Options` に `headRatio?: number` を復元

### 10. `packages/opencode/test/session/prompt-effect.test.ts`

- upstream が削除、ローカルは merge commit のみ → upstream の削除を採用 (`git rm`)

## 発見した問題とその修正

1. **`OscCopier` の private プロパティ衝突**: typecheck で `CliRenderer.lib` は private と報告され代入不可。インターフェースから `lib` / `rendererPtr` を削除し、関数内で `(renderer as any).lib` アクセスに寄せた (過去コミット `bd389d77b` と同等の修正)
2. **Glob / Filesystem の import パス変更**: upstream で `@/util/glob` → `@opencode-ai/shared/util/glob`、`Filesystem` namespace 廃止 → `import * as Filesystem`. compaction.ts と plan.ts で対応
3. **ToolRegistry の依存サービス欠落**: プロジェクト本体は問題なかったが、test/session/prompt.test.ts で Permission / SessionCompaction が解決されず Layer の `never` 制約を満たさないエラー。test 内の layer 定義を修正
4. **bun バージョン不整合**: 上述のとおり 1.3.13 にアップグレードで対応
