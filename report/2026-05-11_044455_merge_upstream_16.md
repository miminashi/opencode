### 学んだこと

- 552 コミット規模のマージで、upstream は keymap システムを `@opentui/keymap` 系の外部パッケージへ全面移行（`useKeyboard`/`useKeybind`/`useTextareaKeybindings` → `useBindings`/`tuiConfig.keybinds.get`）。fork 側で残っていた古い API は全面置換が必要だった。`question.tsx` のように UX を保ったまま keybind システムだけ差し替える作業がメイン。
- `Session.plan` は `(session)` から `(session, instance)` に署名変更され、fork 側の plan 周辺コード（prompt.ts × 4、tool/plan.ts × 2）すべての callsite で `InstanceState.context` を yield する必要がある。`Instance` ALS パスから `InstanceState` Effect パスへの統一が進んでいる。
- `ToolRegistry.layer` のローカル拡張（`Permission.Service` + `SessionCompaction.Service` 要求）はテスト側の Layer 構成を壊し続ける。`SessionCompaction.defaultLayer` は深い依存をランタイム提供（TestInstance/InstanceState）に頼るので `Layer.provide` ではなく `Layer.provideMerge` で吸収する必要があった（merge-upstream-15 の `prompt.test.ts` パターンと同じ）。
- `retry.ts` の `return "Tool call parse error, retrying"` （fork 由来）は upstream の Retryable オブジェクト型と非互換になっていた既存バグ。merge-upstream-16 で typecheck が通らなくなって初めて顕在化。
- メインリポの dev 作業ツリーに長期残留の未コミット doc/script 編集があると ff merge が失敗する。次回以降は merge-upstream の前にメインリポの `git status` を必ず確認し、wip があれば事前にコミットしておくこと。
- `bun install --cwd <path>` は worktree のインストールに使えるが、main repo と worktree で別々に実行する必要がある（共有されない）。
