### 学んだこと

- **RuntimeFlags 移行が広範囲に波及**: `Flag.OPENCODE_EXPERIMENTAL_*` の多くが `flags.experimentalXxx`（`RuntimeFlags.Service`）に移行された。`tool/registry.ts` の Layer 要求にも `RuntimeFlags.Service` が追加され、テスト側（`registry.test.ts`）の Layer 構成も `registryLayer(flags)` のように関数化される。fork 側で `Flag.OPENCODE_EXPERIMENTAL_LSP_TOOL` 等を残していると typecheck で確実に弾かれる。
- **Zod 削除が `namedSchemaError` ヘルパー除去に直結**: `namedSchemaError` が `@opencode-ai/core/schema` から削除されたため、fork で残っていた 2 か所（`auth.ts` の `OauthAuthorizeFailed`、`message-v2.ts` の `StallTimeoutError`）がそれぞれ別パターンに移行が必要。`OauthAuthorizeFailed` は `Schema.TaggedErrorClass` + `cause: Schema.optional(Schema.Defect)`、`StallTimeoutError` は `NamedError.create`。`Schema.TaggedErrorClass` の `MakeOptions` は `cause` を受けないので、コンストラクタの呼び出し方も `new Err({}, { cause: e })` → `new Err({ cause: e })` に書き換える必要がある。`Provider.ModelNotFoundError` が手本になる。
- **Test API 全面 Effect 化**: `WithInstance.provide({ directory: tmp.path, fn: async () => {...} })` 形式は完全廃止。新形式は `it.instance("title", () => Effect.gen(function* () {...}))`。`load` も `(svc) => Effect.Effect<A>` を取る形に変わった。fork が追加していたテスト（`agent.test.ts` の plan/explore 拘束テスト等）はこのパターンに書き換えが必須。
- **`getLastModel` のような fork ローカルヘルパーがコンフリクト解消で消えやすい**: merge-upstream-16 でも `tool/plan.ts` の `InstanceState.context` を消してしまって後から戻したのと同じパターン。3-way マージの片側だけで定義されている小さな関数はコンフリクト解消時に視野から外れがち。
- **GPU サーバの安定性は当てにできない**: 動作確認の途中で iLO + LLM サーバの両方が同時にネットワーク不通になることがある。「LLM サーバー前提条件」チェックは作業開始時に行うものの、長時間タスクの途中で落ちるケースには別途観測手段が必要。今回は復旧後に再テストして応答受信まで完遂できたが、ネットワーク切断後に opencode TUI の SSE ストリームがフリーズ（プロンプトが "QUEUED" のまま進まない、Esc 中断も効かない）したため、TUI 再起動が必要だった。
- **動作確認は新規セッションで行う**: ネットワーク不通を挟むとセッション側の processing state がスタックし、後続プロンプトが恒久的に QUEUED になる。復旧後は既存セッションの継続ではなく、TUI を kill して新規セッションで投入し直すのが確実。
