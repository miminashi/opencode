## 発見した問題とその修正

### コード起因の問題

なし。コンフリクト・ビルドエラー・型エラー・FAIL すべてゼロ。

唯一の WARN (Phase E-1) は LLM (Qwen3.6-35B-A3B) が `seq 1 3000` プロンプトを bash ツール経由ではなく自身の知識から直接答えた挙動で、fork コードの変更ではない。E-2 で truncation retry コード (`truncationRetryCount`, `MAX_TRUNCATION_RETRIES`, `truncated tool call detected` log) の健在性は確認済み。

### ワークフロー運用上の問題 (skill 待機ループの詰まり)

`fork-regression-test` skill の待機ループが **2 回詰まり、手動介入が必要**だった。詳細はリグレッションレポートの「ワークフロー停止事象」セクション参照:

1. **Phase B-4 詰まり (約 30 分)**: 改稿指示後に LLM が `plan_exit` ではなく `ask_question` を呼び、待機ループの grep パターン (`auto-accept edits`) が刺さらず GPU アイドルのまま放置された。ユーザの指摘で発覚 → Escape + 明示プロンプトで plan_exit 再呼出して回避。
2. **Phase E-1 詰まり (約 15 分)**: `seq 1 3000` プロンプトに対し LLM が bash ツールを呼ばずに知識から直接回答。truncation マーカー (`truncated`) が出ず待機ループが空回り。5 分間隔の定期確認で発覚 → WARN 判定で skip して次の grep ベースの E-2/E-3 に進行。

これらは fork コードのリグレッションではなく、**skill 自身の待機ロジックが LLM の経路外れ (別ツール選択 / 知識回答) を検出できない設計上の弱点**による。詳細な root cause 分析と改善候補 4 件は[リグレッションレポート](./2026-05-25_041418_fork-regression-merge-upstream-22.md)に記載。次回 skill 改善時に取り込み候補。
