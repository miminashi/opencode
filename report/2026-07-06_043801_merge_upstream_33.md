### Learnings（次回マージへの申し送り）

- **`session/compaction.ts` の fork 拡張が根強い**: fork の `discoverStateFiles`（`.opencode/plans/*_STATE.json` 経由の状態ファイル探索）は今回も維持。imports に `path`/`Glob`/`Filesystem` が必要になるが、これらは fork 独自の追加なので upstream 側との re-import 衝突を疑うポイント
- **`registry.ts` の `defaultLayer` export は完全に用済み**: `Layer.suspend + Layer.provide` パイプの旧 export は m-33 時点で fork 内から参照ゼロ。次回以降のマージで残っていたら削除して良い（LayerNode.make が既に正規経路）
- **`tool/registry.ts` の `LayerNode.make.deps` は毎回チェック**: 今回も `Permission.node` + `SessionCompaction.node` を復元。加えて upstream が新規に追加した `Ripgrep.node` は取り込む必要がある。**deps の変化は「fork 独自 (Permission/SessionCompaction) を復元 × upstream 新規 (Ripgrep 等) を追加」の両側マージ**が正解
- **`test/session/prompt.test.ts` の Layer.mergeAll 系は upstream の LayerNode.compile に丸ごと置換**: これは upstream 経由で LayerNode migration が浸透しており、fork 側の旧 API 呼出は defaultLayer 消滅で即座にビルド不可になる。次回は当初から upstream 版で解消するのが正解
- **help-snapshots の指標**: fork が `--thinking [default: true]` を保持している限り、snap の該当行に `[default: true]` を残す必要がある。それ以外の diff（`--dangerously-skip-permissions` 表示による indent 幅の差など）は hidden option の可視差で、実行時の help 出力は upstream の short-indent 版と一致する
