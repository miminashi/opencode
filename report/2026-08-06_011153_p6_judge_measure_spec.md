# judge 計測基準書の制定 — 計測方法の正本を一箇所に固定

- 日時: 2026-08-06 01:11 JST
- 作成者: Claude

## 概要

phase 6 judge（permission 判定役 LLM）の計測方法を明文化した正本ドキュメント `tmp/p6-judge/MEASURE_SPEC.md`（version 1）を制定した。これまで計測方法は 23 本のレポート・`tmp/` 直下と `tmp/feat-bench/` に散在するスクリプト・版管理宣言のないラベル TSV に分散しており、独立した手順書が存在しなかった。8/5 に踏んだ循環性事故（正解ラベルがパス規則の関数であることに気づかず、新しい物差しで同じ構造を再生産した件）の一因もこの文書不在にある。

制定の直接のきっかけは、judge の位置づけを「正確な裁定器」から「理由付きの deny で主モデルの再考を促す装置」へ捉え直す方針議論である。この機構モデルに立つと、現行の verdict 一致率（recall / specificity）は因果連鎖の最初の一段しか測っておらず、理由の正しさと deny 後の主モデルの行動を測る新しい物差し（v3・3 層計測）が必要になる。基準書はその v3 仕様と、現行物差し（corpus B v2）の定義・既知の落とし穴レジスタの両方を収録し、今後の計測はすべて本書を起点とする体制にした。

執筆前の調査で重要な新事実が 1 つ確定した。**judge の deny 理由は既に主モデルへ届いている**。live プラグインが deny 時に理由文字列入りの例外を投げ、それが tool のエラーテキストとして会話履歴に入る経路をコードで確認した。当初「配線確認」は v3 の前提課題としていたが、確認済みの事実として基準書に経路ごと記録する形に変わった。あわせて、2/3 多数決が corpus B 計測には含まれない（前段の FP 系列の手法である）こと、dev/holdout 分割が既に存在すること、live は judge の reasoning を文字数しか保存しないため理由分析は replay データで行う必要があることも調査で確定し、基準書に反映した。

また、ユーザの依頼により CLAUDE.md に「phase 6 judge 計測」節を追加し、正本への参照と要点（v2 ラベル使用・feature-bench の同名「judge」との区別・v3 スクリプトの置き場所）を記載した。

## 前提条件・目的

- 目的: phase 6 judge の計測方法（正解ラベルの作り方・指標定義・落とし穴・新物差し仕様）を一箇所に固定し、循環性事故のような「物差し起因の誤結論」の再発を防ぐ
- 背景: 判定役モデル構想の出発点（主モデルが拒否で考えを改める挙動）に立ち返る議論があり、「deny の理由がちゃんと述べられていることが重要で、多少 deny 側に振ってもよいのではないか」という問いから、物差し自体を機構モデルに揃えて組み替える方針が合意された
- ディレクトリ名 `tmp/p6-judge/` はユーザ承認済み（feature-bench の「judge」= シナリオ主観採点との多義性を避けるため `judge` 単独は不採用）

## 結果・所見

- **成果物**: `tmp/p6-judge/MEASURE_SPEC.md`（version 1）と CLAUDE.md の参照節。今後 judge の計測・採点・レポート作成はこの基準書を起点とする
- **配線の確認結果**: deny 理由は `plugins/phase6-verify/index.mjs:254-256` の throw → tool errorText 経路で主モデルの会話履歴に入る（opencode 本体の permission ask フローとは別経路）。v3 第 2 層（deny 後行動ベンチ）の live 妥当性の前提が成立していることを意味する
- **調査で正確化された点**: 2/3 多数決は corpus B 計測のスコープ外 / `missing` と fail-open は別勘定 / live は reasoning 非保存のため理由採点は replay データ前提 / corpus rev の混在参照（build は rev5、audit_bash_labels は rev6）という運用注意
- **残課題**: v3 第 2 層の設計課題 4 点（会話履歴の再構成方法・リプレイ起点・後続行動分類の自動化・観測範囲）は未確定であり、着手時に基準書を改版して確定させる。第 1 層（正当理由 deny 率）は規準ファイル `reason_rubric.md` の作成から始められる（GPU 不要・既存 replay データで完結）
- **教訓**: サブエージェント調査の参照レポート引用は 4 件中 2 件が「日付は合うが内容が別レポート」だった。引用は内容 grep で裏取りしてから確定する運用が有効だった
