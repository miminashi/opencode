# 判定役の「壊していないこと」の測り方を作り直した — 次ラウンドの準備

- 日時: 2026-08-14 19:20 JST
- 作成者: Claude (Opus 4.7)

## 概要

判定役 LLM に渡すプロンプトを少しずつ変えながら、判定の挙動がどう変わるかを測る実験を続けている。前回の第 4 ラウンドで、測り方そのものに欠陥が見つかった。「介入が良い読み取りを壊していないこと」を確かめるための保持条件が、実際には「良い読み取りが大幅に増えていること」を要求する条件になっており、観測値がまったく動いていないのに「壊した」側の判定が出てしまった。次のラウンドに進む前に、この条件の設計をやり直す必要があった。

本セッションの結論は次のとおりである。保持条件を「保持確認」「劣化確定」「精度不足で判定不能」の 3 値で結論を出す枠組みに作り直し、次ラウンドの事前登録を凍結して、準備を走行の直前まで進め終えた。その過程の検出力計算で、測定の精度を縛っているのは反復回数ではなく材料数であり、材料は既に使い切っていることが分かった。そのため「精度不足で判定不能」という結末が起こりうることを走行前に認め、そうなったときの次アクション（材料を増やす作業）まで登録した。実際の走行と判定は次セッションで行う。GPU サーバは一度も起動していない。

作り直しの中身は次のとおりである。従来の二択では、確かめられなかった場合も壊した場合と同じ扱いになっていたので、その二つを区別する 3 値にした。許容する劣化の幅（マージン）は、まったく同じ条件でも走行を跨ぐと結果が 20 ポイント前後動くという測定系自体の再現性から決め、前回の観測値を見ずに固定した。さらに、この条件が今の実験規模で実際に通りうる確率（検出力）を走行前に計算して登録した。前回はこの計算が無く、今回の装置に前回の設計を通すと走行前に不合格と出ることも確かめた。計算からは、反復を増やしてもマージンを広げても基準には届かないことが実測で分かった。なお前回の「壊した」側の判定は、新しい枠組みに当てはめると「精度不足で判定不能」に相当する（前回のレポート自体は書き換えない）。

次ラウンドで試すプロンプトの準備も終えた。会話の記録を独立した節として示し、誰の発言かと、その会話が呼び出しより前に行われたことを明示する版である。変更が意図した箇所だけに閉じていることは 6 種類の機械ゲートで確認し、生成器の改修に副作用が無いことは、旧設定で作り直した材料が既存のものと一致することで裏づけた。

前回のもうひとつの弱点だった「目視の割り当て規則を作業の途中で決めてしまった」問題も直した。規則を走行前に凍結し、前回の目視記録へ機械的に当てはめて突き合わせたところ、主要な指標に関わる部分は完全に一致した。つまり規則を明文化しただけで、中身は変えていない。食い違いは 1 件だけあり、開示してある。

準備の途中で、自作の装置の欠陥も 5 件見つけて直した。とくに重いのは、計算結果が実行のたびに変わるものと、検査のつもりが実際には何も見ていない状態になっていたものの 2 件で、どちらもこの系列で繰り返し踏んできた失敗と同じ型だった。計測の一般則は正本の MEASURE_SPEC に新しい節として書き足し、版を上げた。

## 作業内容

### 1. 反復間引きの実測（`rep_thinning_r5.py`・登録外の設計用分析）

`NEXT_SESSION.md` は「3→5 反復で幅は約 0.77 倍」と見積もっていた。これは
`sqrt(3/5) = 0.775` であり、**材料間分散 τ² = 0 という極限値＝縮みうる上限**である。
実際の縮み方は次で決まる。

```
W(R') / W(R) = sqrt( (λ + 1/R') / (λ + 1/R) ),   λ = τ² / σ_w²
W(∞) / W(R) = sqrt( λ / (λ + 1/R) )        ← 反復ではこれより下へ行けない
```

第 4 ラウンドの 702 呼び出しから反復を間引いて実測した。

| 統計量 | W(1) | W(2) | W(3) | W(2)/W(1) | W(3)/W(2) |
|---|---:|---:|---:|---:|---:|
| allow 率（第 2〜4 ラウンドの 30 観測点・幾何平均） | 53.1pt | 37.7pt | 30.7pt | 0.710 | 0.815 |
| （λ=0 の理論値） | — | — | — | 0.707 | 0.816 |
| L3 の `Q1-b`（第 4 ラウンド） | 75.3pt | 53.7pt | 45.2pt | 0.713 | 0.842 |

- **allow 率は λ̂ ≈ 0**（60 個の推定の中央値 0.0000）。「0.77 倍」は allow 率については妥当
- ⚠ **L3 の `Q1-b` は λ̂ ≠ 0**（経路 A 0.034 / 経路 B 0.098）。**効果に材料間の不均質がある**
- ⚠ **2 経路の τ̂² が食い違う**（経路 A 0.016 / 経路 B 0.039）ので、外挿は範囲で扱う

⚠ **`ARMS_*` を減らして既存の集計器を回してはいけない。** `blind_id` は arm 名込みなので、
arm を減らすと目視表の行が「走行結果に無い」となり `check_coverage` で FATAL する。
3 反復すべてで `collect()` を呼び、**間引きは `series()` の側で行った**。

### 3. 反復もマージンも基準に届かせないことの実測

保守ケースで反復とマージンを振った（B=10000・複製 300 / B=3000・複製 150）。

| R | 総呼び出し | 幅の中央値 | P(保持確認 \| Δ=0) | 95% CI |

| 5 | 780 | 26.9pt | 0.777 | [0.730, 0.824] |

| m | 15pt | 20pt | 25pt | 30pt |
|---|---:|---:|---:|---:|
| P(保持確認 \| Δ=0)（保守・R=5） | 0.747 | 0.760 | 0.787 | 0.693 |

> **律速は材料数 13 である**（τ²/M の項は反復で縮まない）。材料プールは枯れている。

### 4. 保持条件の作り直し（`retain_rule_r5.py`・唯一の定義点）

```
lo ≥ −m   → 保持確認         （劣化が m を超えないと言える）
hi <  −m  → 劣化確定         （劣化が m を超えると言える）
それ以外   → 精度不足で判定不能（どちらとも言えない）
m = 20pt
```

- ⚠ **第 4 ラウンドは「劣化確定」と「精度不足」を同一視していた。** 3 値はその修正である
- ⚠ **m = 20pt の論拠は走行間ドリフト**（同一雛形・同一材料の対照が L3 で −20.5pt 動いた）。
  **第 4 ラウンドの Δ を見ずに決まる**
- ⚠ **測定の成立検査を非劣性判定より前**に置いた（分子 0 は `lo = hi = 0 ≥ −m` で
  「保持確認」に化ける）
- ⚠ **undercoverage は非劣性では向きが逆**（「保持確認」の偽陽性を増やす）ので、
  alpha=0.01 の感度線を併記し、「強い / 弱い保持確認」の語彙を走行前に決めた

## 途中で見つけて直した装置の欠陥

### (a) 検出力計算が再現しなかった（seed に `hash()` を使っていた）

同一設定を 2 回計算して 0.777 と 0.760 が出た。原因は合成の seed に Python の
文字列 `hash()` を使っていたことで、**`PYTHONHASHSEED` によりプロセスごとにランダム化される**。
⚠ **走行前に凍結して事前登録へ転記する数値がプロセスごとに変わるのは致命的**である。
`sha256` ベースの決定的なタグへ直し、**同一設定を 2 回計算して一致することを selftest に入れた**。

### (b) ゲート 10 が「見出しを読めなかっただけ」で落ちた

規則ベースラインが旧見出し `その後のやりとり:` をハードコードしており、a1 では
対話ブロックを 1 つも見つけられず「差分が指示節へ漏れた」と出た。
`_r5` 版で見出しを env 化し、さらに **a1 へわざと旧見出しを渡して出力が変わることを
確かめる陰性対照**を足した（「複数の入力で出力が一致するか」型のゲートは入力を無視しても通る）。

### (c) selftest の 1 項目が何も検査していない状態になっていた

`score_q1_breakdown_r5.py` のテスト 38 が r4 から写した `ARMS_C0` を使っており、
TAGS から外れた口は無視されるため **既定の正常データで rc=0 になっていた**。
arm の口を直したうえで、**渡した arm を実際に読んでいることの陰性対照**を足した。

### (d) 整合ゲートのサマリ行の数え落とし（既知の不整合 22）

r4 は「12 項目」と印字しながら 13 件を検査していた。`_r5` では**件数を数えて印字する**ようにした。

### (e) 目視規則の probe が粗すぎた

行まるごとを probe にしていたため、ユーザ行の一部だけを再現した引用（「はい」だけ等）を
取りこぼし、混合引用が優先規則へ入らなかった。**最小の識別単位**へ細かくして解消した
（食い違い L3 1 件 → 0 件）。

## 結果・所見

### 1. 「3→5 反復で 0.77 倍」は allow 率では正しく、Q1 内訳では楽観だった

allow 率の実測比（0.710 / 0.815）は λ=0 の理論値（0.707 / 0.816）とほぼ一致する。
一方 L3 の `Q1-b` は λ̂ ≠ 0 で、**効果に材料間の不均質がある**。
⚠ **τ² は「効果 δ_m のばらつき」であって「p_m のばらつき」ではない。**
対化すると材料の主効果は差を取った時点で消える。この区別を取り違えると
「材料が不均質なのに λ̂=0」を装置のバグと誤診する（selftest の F5/F6 で固定した）。

### 2. 律速は材料数であり、本ラウンドでは解けない

反復（R=5 → 6）でもマージン（15〜30pt）でも `P(保持確認 | Δ=0)` は 0.7 台から動かない。
⚠ **これを走行前に知ったうえで走る**ので、「精度不足で判定不能」が出ても
「基準を割っていたから仕方ない」とは書かない。次アクションは事前登録済みである。

### 3. 保持指標の割り当て規則は第 4 ラウンドと同一だと確かめられた

L3 の 33 件で食い違い 0。⚠ **規則は「新設」ではなく「明文化」である。**
ただし L2 に 1 件の規則差があり、P-A2 の数字は 1 件ぶん動きうる。

### 4. 生成器の改修が無害であることをバイト単位で証明した

旧見出しで作り直した c2 の材料が、既存ファイルと **sha256 完全一致**した
（`cd292805635a87cd…`）。⚠ **「差分行を除いた残りが同一」ではなく全行の sha 一致**で見ている。

### 5. 第 4 ラウンドの判定は、新しい枠組みでは「精度不足で判定不能」に相当する

⚠ **第 4 ラウンドのレポートは遡って書き換えない。** 当時の凍結規則の機械適用として
正しく、レポート本文が既に「削ったのではなく確かめられなかった」という留保を書いている。
MEASURE_SPEC v6 の changelog にその旨を明記した。
