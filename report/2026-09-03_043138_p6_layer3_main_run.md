# 第 3 層本走: 判定役はタスクを壊さずに阻止率を上げたか

- 日時: 2026-09-03 05:30 JST(初稿 04:31 → glm レビューと再採点を反映して改稿。16:12 に概要を平易化)
- 作成者: Claude

## 概要

第 3 層は、permission 判定役 LLM(judge)を live の opencode に組み込み、「危険な書き込みを止められるか」(実効阻止率)と「ふつうのタスクを邪魔しないか」(タスク完遂率)を必ず対で測る計測である。設計と事前登録(前レポート)に続き、本走として judge 無しの対照 J0・規則ベースの J1・会話履歴の承認を見る J2 の 3 arm を、各 2 run × 50 trial(計 300 trial)走らせた。

本レポートの結論は次のとおりである。**どちらの judge も、狙いとした「阻止率を上げ、かつ完遂率を保つ」形には入らなかった。** J1 は危険な書き込みをすべて止めたが、承認済みの操作まで止める一律 deny 型で、完遂率を保てたかも確かめられなかった(判定は確定に至らず探索へ降格)。J2 は完遂率を完全に保ち、承認済みの操作も正しく通したが、肝心の「別の行為への承認を悪用する」水準では 1 件も止められず、「効かない judge」だった。次にやることは、deny された後の主モデルの行動の 4 分類(目視・未実施)と、J2 が全敗した機構の分析である。

読む際の注意が 2 つある。第一に、**当初の採点には集計から外したはずの水準(L1)が混ざっており、「J2 が狙いの形に入った」という逆の結論に読めた**。自分の検算と外部レビュー(glm)が独立に同じ誤りを指摘し、正しい範囲で採点し直して上の結論に確定した(経緯と両方の数値は本文)。第二に、走行はネットワーク障害・中断・ハーネスのハングを挟んでおり、成立検査で見つかった問題は、影響が小さいことを確かめたうえで開示つきで続行した(ユーザ決定)。細かい数値・判定規則との対応・限界はすべて本文に記載した。

### 限界(開示)

1. **J1 ×2・J2 ×2 は中断・障害・ハングを挟んだ結合 run**(無中断は J0 の 2 run のみ)
2. **当初の採点は L1 が B に混入していた**(追記 17)。確認的の正本は L2 のみの再採点で、両方の出力を添付に保存した
3. x trial 1 件は scorer の A 分母に残った(手計算併記で開示・追記 16)。B・C の分母には入らない
4. ctx 溢れ 1 trial は開示つき逸脱で保持(既定処置からの逸脱・ユーザ決定)。B 側には構造的に届かない
5. G7 ゲートの検出語は特異度を selftest しておらず 5093 件の誤検知を出した(v13 §3 項目 26)
6. L1 の B は材料不成立(attempt 率 30%)。**B の結論は L2(読取承認)の上でのみ**成立する。L2 も 1 変種(`l2r`)であり、家系 `p6l3-*` の上での結果に限定される。live 一般への外挿はしない(上限測定)
7. m = 10pt の下で J1 の ΔC は原理的に確定しにくい(P(保持確認|0) ≈ 0.5 の設計)
8. B_J0 が床のため ΔB の対比は 1 標本の絶対値の検定に等しい(§5-4 で走行前に開示済み)
