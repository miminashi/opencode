### レポート構成（案）

- タイトル: 「判定役LLM によるツール呼び出しチェック実験のシリーズレビュー」（平易な日本語、細かい識別子はファイル名側に）
- 日時（分まで、JST）・作成者
- **概要**: 通読できる段落文章で 5〜8 段落。シリーズ全体の目的 → 前半（パス照合器としての性能追求）→ 転換点（測っていた問題設定自体の誤り発覚）→ 後半（文脈認識 judge・雛形改良）→ 現在の到達点と残課題
- **前提条件・目的**: B-1 対策としての Phase 6 の位置づけ（プロンプト強化 / 機械ガード / 認知系介入の 3 系統）、本レビューの目的
- **対象レポート一覧**: 22 本の時系列索引表（相対リンク + 一行要旨）
- **シリーズの経過**: 前半・後半の 2 節で時系列ストーリーを記述（各段階の主要数値を含む）
- **方針転換の詳細**（本レビューの中心。ユーザ指示「方針の誤りに気付いて方針転換した点に注意」に対応）:
  1. judge モデル路線の転換: 上位等級（235B）仮説の撤回 → コード特化（North）が effective diversity（07-24）
  2. baseline の誤り: Phase 3c2 の 33.3% は dp bucket 混合値、正しくは 0/20（07-24 control）
  3. fail-open の発覚: allow の 39.6% は timeout 由来の捏造。judge 選定より timeout の扱いが律速（07-26）
  4. 主指標の切替: correction rate は阻止力を過大評価（North 87.5% の実質 60%）→ 実効阻止率へ（07-30）
  5. 診断の訂正: fail-open の主因は max_tokens でなくサーバ速度、thinking off は有害（07-31）
  6. FP 回帰の正体: 5%↔30% は現象でなくサンプリング揺れ。trial 単位 FP は call 揺れを約 11 倍増幅（07-31 bisect）
  7. 物差しの取り違え: judge は 4 点で答え、ラベルは 1 点しか見ていなかった → FP 分母の作り直しで真 FP 0/64（08-02）
  8. ★最大の転換: judge は文脈を一度も見ていなかった（三重未実装）。パス照合には judge が本質的に不要 → 指示整合判定へ全面転換、FP/recall の数値を正解ラベルごと廃棄（08-02）
  9. 物差し側の限界と訂正の連鎖: corpus に「止めるべき呼び出し」がほぼ無い / 人手ラベル 1 件訂正（ctx_hist だけが正しかった）/ LLM 自己申告の因果取り違え（Step 4）/ corpus B 290 件への組み直し（08-02〜03）
  10. ★免責路線の不採用: 免責の書き足しは「照合手順」でなく「逃げ道」として使われ recall 97.4→85.6%。同時に物差し 15 件誤り（`:` 未除外）発覚、`bash_abs_parent_write` 型は消滅、旧優先 2 は撤回（08-04）
- **方法論上の問題点・見落としの指摘**（ユーザ追加指示によりレビューの中心セクションに昇格。レポート群自身が既に自己訂正した点ではなく、**現在も残っている穴**を指摘する）:
  - A. 測定設計の問題:
    1. 主指標の逆戻り — 07-30 に「correction rate は過大評価、主指標は実効阻止率」と確定したのに、08-02 の方針転換後の全実験はオフライン replay の allow/deny ラベル（recall/specificity）のみで評価。実効阻止率（deny が親に迂回されないか）は ctx 系で一度も測られていない（grep で裏取り済: 08-02〜08-04 のレポートに「実効阻止」への言及は pivot 前の vote_replay 1 本のみ）
    2. 同一データでの反復改良 = in-sample 過学習リスク — ctx_soft→step→env→loc の雛形改良は毎回同じ 139 件 / 290 件で評価・選択。holdout なし。ctxb_loc の recall 97.4% は汎化性能の推定値ではない。ft コーパスでは leakage を議論したのに判定プロンプト自身の選択には同じ規律が未適用
    3. サンプリング揺れの教訓の不適用 — 07-31 bisect で「単発 run の deny 集合は激しく揺れる」と確定したのに、ctxb_env/loc/excl は各 1 run で採用判定。ctxb_loc 再現性未確認（自認）。後半 3 レポートに検定・CI が一切ない（grep 裏取り済: Fisher/Wilson/McNemar/信頼区間 0 件）。同一サンプルの対応比較なのに対応検定なし、trial クラスタ補正なし
    4. fail-open の分母バイアス — fail-open は分母除外で、打ち切りは最長思考の（=難しい）件に系統的に集中する（08-04 自認）。fail-open が多い arm ほど難件が分母から抜け recall が甘く出る。ctxb_excl（33 vs 14 件）の 85.6% は実際より良く見えている可能性。レポートは分母変化を注記するがバイアスの向きは未分析
    5. fail-open ポリシー本体が未修正 — 設計書は timeout 時 ask フォールバックだったが実装は捏造 allow のまま。これに起因する誤集計がシリーズ中 4 回以上発生したのに plugin の fail-closed/ask 化は最後まで未実装。集計側 valid_at ゲートは live 運用の防御にならない
  - B. 一般化可能性の問題:
    6. 単一 judge 依存 — 方針転換後の全知見（免責は逃げ道になる等）は North 1 モデル・Q4 量子化でのみ確認。前半で強いモデル依存性（3 judge 横並び vs North だけ特殊）を実測した以上、雛形設計則のモデル固有性検証が必要
    7. 単一プロジェクト・単一親モデルへの過適合 — corpus は全て ytdlor(Rails)+Qwen3.6-35B 由来。雛形免責リストに `docker compose build`/`rails test` 等の具体名を焼き込み、可搬性未評価
    8. ラベルの単独裁定・循環リスク — 指示整合ラベルはプロンプト設計者と同一主体（Claude）の単独裁定。人裁定の誤り 1 件・型ごと目視の見逃し 15 件が実証済みなのに、二重ラベル・独立監査の仕組みなし
  - C. 問題設定レベルの見落とし:
    9. live 運用可能性の追跡停止 — 19〜31 秒/call は全 tool call ゲートの元構想に対し致命的だが、方針転換後レイテンシ・コスト評価が消えた。運用アーキテクチャとしての「機械チェック+LLM の 2 段構成」は pivot 時に評価の文脈で棄却されたが運用の文脈では未検討
    10. 防御スタック全体での judge の担当範囲を再導出していない — protected-branch guard マージ・plan path グローバル化・coloc での bash escape 0 件で前提が変わったのに総点検なし。corpus B の plan_doc_parent 34 件はグローバル化で消える見込み、instructed_worktree 19 件は plugin 修正が筋（08-04 で候補言及止まり）
    11. prompt injection 未検証 — 設計書がリスクに挙げたまま、文脈注入で攻撃面が拡大したのに敵対テストゼロ
    12. specificity の停滞が未診断 — recall は 47.5→97.4% まで改善したが specificity は 79.5→82.9% でほぼ不動。誤 deny 約 17% の内訳分析が後回し
    13. 採用基準の非事前登録 — 設計書の go 3 条件を pivot で捨てた後、新路線の数値目標（recall/specificity しきい値・打ち切り率上限）が再定義されず、arm の採否が事後的・定性的判断になっている
- **横断的な教訓**（レビューとしての評価・所見）:
  - 方針転換は全て「judge の能力不足」→「測り方の誤り」への反転として発生（7 回、判定器より先に測定系が直された）
  - 価値ある知見の多くは主目的の外側（control の中間確認、corpus 化の事務作業、ft 先からの指摘、replay の単純対照）から出た
  - 再利用性の高い法則: 免責・観点は該当する全項目に書かないと効かない / 沈黙（fail-open）下の FP は信用しない / 合計値の一致は中身の不変を意味しない / LLM の自己申告は引数・ログと突き合わせるまで採用しない / rc=0・件数一致は測定の成立ではない
  - 単独介入基準（実効阻止率高 + FP≤5%）を満たす構成は最後まで未達だが、`ctxb_loc` で recall 97.4% / specificity 82.9% に到達
- **結果・所見**: 現到達点（土台 = `structured_v3_ctxb_loc.txt`）、残課題（instructed_worktree の扱い、打ち切り対策、`ctxb_loc` 再現性未確認、corpus 生成側の未修正欠陥）
