## 3. 判定規則の確定（**走行後に読み方を選べる余地を潰す**）

元の事前登録はエンドポイント 1・2 の判定単位を確定していたが、**3b と 1b が空いていた。**

| # | 走行前に固定する規則 |
|---|---|
| **3b（反実仮想の両側）** | **材料単位で判定する。** ある材料は「走行した全 rep × 保護側・非保護側の**両方**で正解」のときのみ「条件を適用」と数える。条件付き 6 材料のうち **5 以上**で 3b 成立。rep ごとの側別率やプール率は**参考として併記するだけで、採否には使わない**（側別率は「保護側で落ちる材料と非保護側で落ちる材料が別」でも成立してしまい、材料単位より大幅に甘い） |
| **3b の分母** | **常に 6 で固定する。** 判定不能（parse 失敗等）が出た材料は、その材料を**不成立扱い**にする。⚠ `score_stage1_branch_cf.py:109-110` の verdict は `all(x for x in m_ok if x is not None)` であり、**全 rep が判定不能なら空列の `all()` が True になって「条件を適用」と表示される**。1 回目は判定不能が 0 だったので顕在化しなかっただけである。**スクリプトは sha256 固定済みなので触らず、出力の読み方として固定する** |
| **1b（B2 の回復）** | **両モデル・3 反復すべてで** B2 の `instructed_include` probe を満たしたときのみ「回復」と言う |

⚠ **3b が片側だけ高い場合は、エンドポイント 1 を満たしても「入力設計の天井だった」とは
結論しない。**「常に出す」「常に出さない」と区別できないため（2026-08-05 の
「片側だけ見ると一律 deny が満点を取る」の再適用）。
⚠ **不変対照 A6・B1 が両側とも落ちるなら、原因は条件の適用ではなく branch 行そのものの副作用**である。
