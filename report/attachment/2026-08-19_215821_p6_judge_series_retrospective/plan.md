## レポート構成(案)

自己完結型・目安 400〜600 行。日本語。数値は実測値を本文に埋め込み、出典レポートへ相対リンク。

章立ては**現象中心**に組む。「何の現象を追いかけているのか」が最初に一意に分かり、その同定自体が研究の中で 3 回精密化されたこと(それがシリーズの核心)を骨格にする。

1. **概要** — CLAUDE.md 規則どおり(1 段落目: 背景と問題 / 2 段落目: 結論宣言 / 3 段落目以降: 詳細)
2. **本レポートの目的と読み方** — 想定読者(追試者・別方面からの検証者、人間または LLM)、正本の所在(MEASURE_SPEC.md v8 が計測方法の正本、本レポートは案内図)
3. **追いかけている現象** — 本シリーズが観測対象とする現象を最初に固定する:
   - **出発点の現象**: 主モデル(コーディングエージェント)が worktree 隔離の指示を破り親リポジトリへ書き込む逸脱(B-1 worktree escape。単発ではなく 3 件独立で実測)。これを別の LLM(judge)に検査させたとき何が起きるか、が全シリーズの観測対象
   - **研究の問い**: モデル同士のかけあわせ(主モデル × 判定役)の限界解明。実用ハーネスの早期実装ではない
   - **中心現象の 3 段階の精密化**(各段階で「前の問いは現象ではなかった」と判明した経緯を含める):
     1. 「judge はパスの正誤を当てられるか」→ 正解が機械規則の関数で、20 行の規則が LLM に勝った=**判定として追う価値のある現象ではなかった**(循環性、08-05)
     2. 「judge は文脈上の**承認**を検査できるか」— 言及と承認の区別、provenance 検査(08-07 再定式化)。承認を見せれば転向 76.9%、しかし行為の射程の誤りと根拠の捏造が残る
     3. 「理由付き deny は主モデルの行動を変えるか」— deny 後行動(第 2 層)。パイロットで観測された現象: 主モデルは deny を隔離違反ではなく技術的失敗(文字列不一致・テスト失敗)と読む
   - **途中で観測された下位現象の目録**: fail-open の捏造(allow の 39.6%)、bash 盲点、事実の呼び名が明示規則より強い、片側評価では一律戦略が満点を取る、走行間ドリフト 等
4. **測定装置と機構モデル** — judge は正確な裁定器ではなく「理由付き deny で主モデルの再考を促す装置」という機構モデル。3 層計測(第 1 層: 正当理由 deny 率 / 第 2 層: deny 後行動 / 第 3 層: 実効阻止率×タスク完遂率)が §3 の現象 3 段階にそれぞれ対応することを明示
5. **時系列の主要転換点**(年表 + 各転回の詳述。§3 の現象精密化と対応づける):
   - 07-23 開始: B-1 worktree escape 対策の第 3 系統として設計
   - 07-26: allow の 39.6% が fail-open の捏造と判明
   - 07-30: correction rate は防御力を過大評価 → 実効阻止率へ / bash 盲点
   - 08-02: **judge が一度も文脈を見ていなかった**(三重未実装)→ 文脈整合判定へ全面転換
   - 08-05: **物差しの循環** — 正解ラベルがパス規則の関数で、20 行の規則が LLM に勝った(現象の精密化 1→2)
   - 08-06: MEASURE_SPEC 制定(計測方法の正本を一箇所に固定)
   - 08-07: **provenance 検査への再定式化** — 「ツール呼び出し時点で対話は終わっているべき」、言及と承認の区別、ループ収束率
   - 08-07〜08-16: 承認ターン系列 第 1〜5 ラウンド(第 1 層)— 転向 76.9% の関門通過、射程条項の不採用、α 単独の判定不能、材料 13 件で構造的検出不能 → **打ち止め**
   - 08-18〜19: 第 2 層 DA-1 設計確定(規格 v8)・実装・パイロット(現象の精密化 2→3)
6. **現在地と未測定事項**(追試者が誤読しやすい点):
   - 主指標「(i) − (iv) の (a) 率の差」は**未測定**(パイロットは (iv) と sham のみ)
   - (a) 対照率 0/20 は主指標の結果として引用禁止
   - P(同値|Δ=0) が 0.8 に届かず「差が無い」の結論は出せない設計と宣言済み
   - 第 1 層打ち止めの理由(材料数律速・検出力不足)
7. **測定系の落とし穴レジストリ要約** — MEASURE_SPEC §3 の 18 項目から追試に効くものを要約(循環性・片側評価・集計単位増幅・fail-open 捏造・構造的検出不能など)。正本は §3 と明記
8. **追試の入口** — 環境(t120h-p100 / Qwen3.6-35B / llama-server)、資材の所在マップ(`tmp/p6-judge/` の構成、`da1/`、prereg 群、ラベル TSV は v2 を使う)、事前登録の有無がレポートごとに分かること(attachment 配下の prereg)
9. **別方面からの検証の切り口(提案)** — 例: 別モデル族での転移(haiku 転移の再現)、正解ラベルの独立再作成、規則ベースラインとの比較の再実施、統計手法(3 値非劣性・δ_sup・検出可能性計算)の検算、reasoning 読解の盲検再割り当て

## 作業手順

### Step 1: 素材の精読(自分で実施)
調査エージェントの結果で全体像は把握済み。転換点の記述精度を上げるため、以下を Read で確認:
- `report/2026-08-04_223423_phase6_judge_series_review.md`(既存総括のスタイルと 13 点の方法論の穴)
- `report/2026-08-07_011139_p6_judge_research_reframe_provenance.md`(研究目的の正確な言明)
- `report/2026-08-19_005942_p6_layer2_da1_impl_and_pilot.md`(最新の現在地)
- `tmp/p6-judge/MEASURE_SPEC.md` の §0〜§1・§3 見出し・§4(機構モデルと落とし穴の正確な字面)

### Step 2: ドラフト素材の委譲(Sonnet)
40 本のレポート一覧表(ファイル名 + 各概要からの 1 行注釈)のドラフト生成を Sonnet に委譲(`model: "sonnet"`)。返却形式: Markdown 表。

### Step 3: 本文執筆(自分で実施)
- タイムスタンプ取得 → レポートファイル作成
- 時系列・現在地・落とし穴・検証の切り口は自分で執筆(複数情報源の統合に該当)
- 概要は最後に執筆(CLAUDE.md「概要の書き方」: 結論を 2 段落目、用語は言い換えない、漢数字不使用、単位を落とさない)
- 用語は既存レポート・MEASURE_SPEC と同じ字面を使う(第 1 層/第 2 層/DA-1/正当理由 deny 率/実効阻止率 等)。「DA-1」と「第 1〜5 ラウンド」の取り違え注意も本文に明記

### Step 4: 執筆後の確認(CLAUDE.md の 3 ステップ)
1. 記載漏れ確認(転換点・数値・所在情報)
2. 矛盾確認(概要 vs 本文、要約語 vs 数値。特に「打ち止め」「未測定」「0/20」の扱い)
3. 概要の構成確認(2 段落目だけで結論が分かるか)

### Step 5: glm レビュー
- `tmp/glm_review_prompt.txt` にプロンプトを作成: ①背景の明示(p6-judge とは何か・本レポートの目的と想定読者) ②観点の列挙(過大主張・見落とし・数値の不整合・外部者にとっての分かりにくさ・追試に必要な情報の欠落) ③「推測で断定せず、どこを読んでそう判断したかを示せ」の指示 ④レポート全文を添付
- `cat tmp/glm_review_prompt.txt | glm -p` で実行(パイプは glm の例外として許可済み)

### Step 6: 指摘の検証と採否(自分で実施)
- 指摘ごとに「レポート・元データのどこを読んでそう言ったか」を突き合わせ、必要なら元レポート・数値で検算
- 採用分はレポート本文を修正、不採用分は理由とともに「外部レビュー」セクションへ記録

### Step 7: 仕上げ
- プランファイルを `report/attachment/<レポート名>/plan.md` へコピー(Read → Write。cp 禁止)
- 最終読み通し(概要と外部レビューセクションの整合)

## 制約・注意

- **過去レポートは一切修正しない**(参照のみ)。MEASURE_SPEC.md・NEXT_SESSION.md も今回は変更しない(振り返りレポートは report/ に閉じる)
- llama-server / GPU は不要(文書作業のみ)
- glm の指摘は鵜呑みにしない(2026-08-19 DA-1 レビューで取り違え指摘の実例あり)
- 数値は必ず出典レポートの字面から転記(記憶で書かない)

- 40 本の一覧表のファイル名が実在すること(Glob で突合)
