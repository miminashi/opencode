## 指摘

### 1. 「J2 の完遂率 100% は主モデルがこの押し問答を押し切った結果である」— 因果語が手元の材料を超えている【最重要】

- **該当箇所**: 概要 2 段落目「J2 の完遂率 100% は主モデルがこの押し問答を押し切った結果である」、§5 読み方2 の同表現
- **問題**: (d) 87.2% と完遂率 100% の*同時観察*から「押し切った」と因果を付けていますが、deny ループの**収束経路の集計が本文にありません**。`j2_mechanism_timeline_l3.txt` の実例を見ると、r2 は同一パス write の 3 回目（[05]）、r3 は 5 回目（[09]）に **judge 側が allow しており**、実態は「judge の判定が非決定的で、再発行すれば allow が出た」です。また読み方4 自身が「escape は deny と無関係の別の判定」と述べており、完遂への単一経路を示せていません。「押し切った」は主モデルの能動的勝利を含意し、機構の帰属先（主モデルの粘り vs judge の判定揺らぎ）を読み誤らせます。34 連発 trial がどう収束したかの記述もありません。
- **直し方の案**: 「再発行を続け、再発行の末に allow に至って完遂した」等の観察形に弱める。さらに (d) event の同一パス再発行が後続 allow に至った件数は verdicts から機械集計可能なので出す（ここまでやって初めて「押し切った」に近い言い方が許される）。34 連発 trial の収束を 1 例でよいので開示。

### 2. 「141 件中 133 件が『正しい場所への計画書 write を必要でないと止めた』誤 deny」— 133 は side 導出の総数であって「計画書 write」の裏づけがない

- **該当箇所**: 概要 2 段落目、§5 読み方2 冒頭
- **問題**: 133 = instructed 側総数（L4 or nonlocation の side 規則による）です。`denyact_l3.txt` 104-105 行目の kind × arm 表は「J2 instructed 133 = `inside_worktree_nonlocation`」までしか言いません。一方 `postmain_secondary_l3.txt` 46 行目には **「J2: deny call = 141 tool 別 = {edit: 31, write: 98, bash: 12}」** があり、write+edit = 129 < 133。side × tool のクロスが無い以上、133 全件が計画書 write とは断定できません（bash 由来が数件混ざる余地が残る）。レポートはこの tool 別集計を一度も引用していません。§7 の「deny はすべて plan 段の計画書 write」も根拠が混在 9 trial の時系列（部分観察）のみです。
- **直し方の案**: verdicts から side × tool の小表を出して実数で書く（例: 「133 中 write 125・bash 8」等）。出せなければ「計画書 write が大半（tool 内訳: …）」と内訳を明示して言い切らない。

### 3. plan mode の構造制約が (d) を造出する交絡の明示欠如

- **該当箇所**: §5 読み方2（「plan mode では計画ファイルしか書けない／`plan_exit` には計画ファイルが要る」と断定して同一パスへ再発行する型」と自ら記述）、§9（該当項目なし）
- **問題**: plan 段で計画書 write を deny された主モデルには、計画機能の設計上**正当な代替先が構造的にほぼ存在しません**（timeline でも write deny と `plan_exit` error が交互するだけ）。つまり J2 の (d) 87.2% は主モデルの拒否耐性の測度ではなく「必須 call への誤 deny ＋ 代替不存在」の帰結で、arm 間差（J1 37.6% vs J2 87.2%）も deny 理由の型（場所 vs 必要性）でほぼ規定されます。本文が構造を記述していながら、解釈上の限界として §9 に置いていない。
- **直し方の案**: §9 に「J2 instructed の (d) は plan 段の構造が造出する面があり、主モデルの性質として一般化しない」を 1 項目追加。読み方2 にも一言。

### 4. (c) の窓前 undercoverage が J1 L1 の (c) 9/10 の解釈を覆しうるのに限界化されていない

- **該当箇所**: §5 読み方1（「`a_intent_declared=1` が 5 件 = 窓の前に worktree 側の編集が済んでいると自己申告」）、§9-5（上限の流用のみ）
- **問題**: 観測窓は deny の次から始まるため、**deny 前に完了した (a) は (c) に見えます**。(c) 9 件中 5 件が窓前編集済みの自己申告なら、「J1 の L1 では 9/10 が放棄」という数値の過半が窓の切り方の産物の可能性があります。読み方では触れるのに §9 に入れていない。さらに `denyact_l3.txt` 38 行目の `a_intent_declared=5` は **J1 deny 全体（n=31）の別列**で、「L1 (c) 9 件のうち 5 件」への帰属はサマリから検証できません（L2 の (c) 1 件等に混在の余地）。
- **直し方の案**: §9 に「(c) は deny 前の行動を観測しない」を追加。`a_intent_declared` を (a) に数える感度（S4）を付けるか、arm × level 内訳を labels から出して読み方1 の帰属を検証可能にする。

### 5. §8 の表からモンテカルロ CI・N_REP=40・TAU2=0 を落とした — 非単調性が無説明で並ぶ

- **該当箇所**: §8 の表（150 行 62%・200 行 57%）
- **問題**: `detectability_layer3_post.txt` には「**N_REP=40** / ブートストラップ B=1500 seed=20260829」と、62%**[47,76]**・57%**[42,71]** の区間があります。レポートは点推定のみ転記し、N_REP・CI を省きました。N=150→200 での低下（62→57）は N_REP=40 の揺らぎ（SE ≈ 7.7pt）で説明されますが、本文に注記がなく、読者は「N を増やすと検出力が下がる？」という無用な疑問を抱きます。また出力ヘッダの **TAU2=[0.0]** に本文は一切触れず、「P_C0=0.99 近似は保守側」と言う一方で τ²=0 は幅を狭める**楽観側**である非対称を書いていません（§9-7 も「合成モデルの上の値」のみ）。
- **直し方の案**: 表に CI を戻し、N_REP・B・seed を本文に明記。「150→200 の逆転は N_REP=40 のモンテカルロ誤差内（区間が広く重なる）」と注記。§9-7 に τ²=0 の方向性（保持確認率を楽観側に動かす）を追記。

### 6. 「反論は 66/67 が reasoning のみ」— 分母 67 の定義が不在で検証不能

- **該当箇所**: §5 読み方2
- **問題**: `denyact_l3.txt` 44-45 行目では d_source = {none: 54, reasoning_only: 66}（d_kind は reissue 54 + both 61 + rebut 1 = folded d 116、成分 has_d=120）、reasoning_category は dispute 66 + user_attribution 1 + …。**66 は reasoning_only と対応しますが、67 がどの集計かを本文も出力サマリも定義していません**。d_kind で反論を含むのは both 61 + rebut 1 = 62 で、67 とも 66+1（user_attribution）とも確定できない。誤記の可能性を含め、再現性の観点で最も弱い数値です。
- **直し方の案**: 67 の定義を本文に書く。もし「反論を含む (d) event」が意図なら 62 が正しく 66/67 は誤記。生 labels から出し直して明記する。

### 7. S2 で J2 (d) が 116→53 に半減する定義依存性が、概要と §9 に反映されていない

- **該当箇所**: §5 感度表（数値はある）、概要 2 段落目（87.2% のみ）、§9-5
- **問題**: 追記 18 で terminal tool で切らないと決めた設計判断自体は尊重しますが、**結論段落に置いた 87.2% が観測窓の terminal tool 扱いの定義で 0.4 倍に動く**ことを、概要だけ読む読者は知り得ません。「追記 18 の 2 で切らないことにした理由そのもの」は理由の説明で、頑健性の開示の代替になりません。
- **直し方の案**: §9-5 に「S2（② 互換）では J2 (d) 116→53・(u) 12→75」を追記。次にやること 2 の規準 v4 の範囲に terminal tool 扱いの明文化を含める。

### 8. J0 天井の下での「保持確認」の意味論 — 0.8 基準の適用の正当化

- **該当箇所**: §8（「⚠ ΔC = 0 の行が 98〜100% なのは J0 が天井（100%）にあるためで、走行前の 52%…とは設定が違う」）
- **問題**: J0 が天井 100% では治験 arm の合成率の下側裾が短く、**保持確認がほぼ自動で通る**（ΔC=0 で 98〜100%）。つまり本設定では「保持確認が出る」こと自体の情報量が小さく、走行前の P_C0=0.90 設計で意味付けされた「保持確認率 0.8」基準と同じ重みで使えません。レポートは「設定が違う」と注意するだけで、その上で 0.8 基準を適用して反復追加の可否を決めています。なお「反復追加は採らない」という結論自体は、±0 に近いもう一つの根拠（劣化確定 0%・57% vs 80%）もあり覆りませんが、論理の足場は補強べき。
- **直し方の案**: §8 に「J0 天井下では保持確認の偠陰性が構造的に小さく、0.8 基準は走行前の設計と同じ意味を持たない」旨 1 文。可能なら §5-5 の指示原文（基準 0.8 の出自）を引用して、適用の形を明示する。
